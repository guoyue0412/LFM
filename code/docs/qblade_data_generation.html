2. QBlade SIL 仿真原理

QBlade 是开源的风机/螺旋桨气动仿真器，SIL（Software In Loop）接口是其 C++ 内核的动态库（.so on Linux），通过 Python ctypes 调用。本项目用的版本是 QBladeCE 2.0.8.6。

2.1 单工况调用序列

QBLADE = QBladeLibrary("libQBladeCE_2.0.8.6.so.1.0.0")
QBLADE.createInstance(0, 8)               # 0=CPU OpenMP, 8 thread
QBLADE.loadSimDefinition(b"RPM5000_Wind10_Angle85.sim")
QBLADE.initializeSimulation()
for i in range(1200):                      # 1200 时间步
    QBLADE.advanceTurbineSimulation()
    if i >= 1080:                           # 末 120 步取均值
        thrust = QBLADE.getCustomData_at_num(b"Aerodynamic Thrust [N]", 0, 0)
        ...
QBLADE.closeInstance()

2.2 关键模型链

文件角色说明

.plr极坐标翼型 Cl/Cd 表（多 Re 数）

3. Free Vortex Wake (FVW) 算法

QBlade 默认使用 LLT Free Vortex Wake 模型 (WAKETYPE=0)。物理上把每个叶片截面视为升力线，每个时间步在尾流中"撒"一组涡环，所有涡环根据流场速度漂移，相互之间产生诱导速度。

3.1 每步算法（伪代码）

step:
  1. 叶片各截面释放新涡环（强度 ∝ 当前升力变化）
  2. 所有现存涡环根据 local velocity 漂移一段距离
  3. 计算所有涡环对叶片截面的 induced velocity：
     v_ind(blade) = Σ_vortex (Γ/(4π) × dl × r / |r|³)
                    └─ Biot-Savart 定律
  4. 涡-涡互相作用（self-induction）：O(N²) 复杂度

3.2 复杂度问题

不截断时，1200 步累积涡环数：

N_vortex = N_blade × N_section × N_step = 2 × 22 × 1200 = 52,800

涡-涡相互作用每步 O(N²) ≈ 2.8×10⁹ 浮点运算，1200 步总计 3.3×10¹² 次运算。

5. 优化历程

FIX 里程碑 1 — .bld 文件 CHORD/TWIST 列错位

症状：仿真从 step 0 就 NaN abort，所有工况无法跑通。

根因：Linux 分支的 Baseline_Blade.bld 文件中 CHORD 列写成了 TWIST 值（55m），TWIST 列写成了 CHORD 值（0.02°）—— 物理上不可解，wake 必然发散。

修复：从 main 分支同步正确的 .bld 文件（commit 265afa4）。

FIX 里程碑 2 — NaN abort 静默写零

症状：仿真 NaN 后子模块未检查 advanceTurbineSimulation 返回值，继续 getCustomData，所有列变 0，混入"无效数据"。

修复：参考 QBlade 官方 sampleScript.py，加 success 检查 + 双重 THRUST 兜底（commit f249608 + 05bb98b）。

PERF #3 跳过 storeProject 写 .qpr

每工况末尾把 13MB QBlade 项目文件落盘 ≈ 60s IO，全规模累计 ~700 小时纯 IO。
训练数据全在 pkl 中，.qpr 仅 GUI 调试用，直接注释掉。
收益：单工况 -60s ≈ 总 28 天。Commit 70fe8e8。

PERF #4 createInstance 跨工况复用

SIMULATION 类原本每工况都 createInstance + closeInstance，OpenCL/OpenMP 初始化 ~4s。
独立测试验证 loadSimDefinition 第二次调用能完全重置内部 wake/state（Thrust 误差 0.0000%）。
重构为 self.QBLADE lazy 创建 + 跨工况复用，跑完 close()。
收益：单工况 init 4.5s → 2.4s（省 2s）≈ 总 23 小时。Commit f249608。

FIX 里程碑 5 — FX 字段恒为 1 bug

症状：mini_v2 验证 pkl 时发现两个工况 FX 都精确等于 1.0000。
根因：QBlade SIL 不暴露 Aerodynamic Force in Hub X_g Direction 变量名，getCustomData_at_num 找不到时返回固定 -1.0，聚合 × -1 → 1.0。
物理上 X 方向力 = 主推力（旋转轴向），就是 Aerodynamic Thrust。
修复：删除 raw Fx 采集，post-process 设 FX = THRUST 别名。Commit ad8b9bb。

PERF #1 Wake 截断（本文档重点）

FVW 涡环每步累加，1200 步累积 5 万涡环，涡-涡相互作用 O(N²) → advance 单步 1.5s。
通过 .trb 文件的 6 个参数限制 wake 长度/数量 → 详见 §6。
预期收益：单步 1.5s → 0.1-0.2s（10-15× 加速）。Commit 5bb79c3。

6.3 物理依据

Lamb-Oseen 涡的诱导速度：v_ind(r) ∝ Γ / (2π·r) × [1 - exp(-r²/r_c²)]
远场（r >> r_c）：v_ind ≈ Γ / (2π·r)，r 越大贡献越小（~1/r）

对叶片受力的影响：距离 r 处的涡通过 Biot-Savart 贡献的力 ∝ 1/r²。

截断距离远场贡献推力误差
100R（默认）100%（基准）0%
20R~99%< 1%
10R（优化）~95%< 3%
5R~85%~10%（过紧）

7.3 Wake 截断为何没有加速？

关键发现：当前配置下 wake 截断对 1200 步 + RPM 5000-6000 工况几乎不省时间，原因如下：
  1. MAXWAKEDIST 截断从未触发：
    • 1200 步 × dt 0.000083s = 0.1 秒仿真时长
    • Wind 10 m/s 漂移距离 = 0.1s × 10m/s = 1 米
    • MAXWAKEDIST = 10D = 2.5 米，阈值远未达到
  2. ZONE length 截断只在最后 22% 时间生效：
    • 总 wake 长度 = NEAR(0.5) + ZONE1(1) + ZONE2(2) + ZONE3(3) = 6.5 转
    • 6.5 转 ÷ 83 转/s ≈ 0.078s ≈ step 940
    • step 0-940 处于累积期（wake 尚未填满），step 940-1200 才截断
  3. ZONE3FACTOR=8 远场粗化收益小：远场涡通过 1/r² 衰减，本就贡献微弱
真正瓶颈仍在累积期前 940 步的 O(N²) 涡-涡相互作用，1200 步深仿真无法绕开此固有开销。

8. node6 16 worker 并行架构

8.1 硬件配置（node6）

资源规格
CPU160 核（实际可调度 ~150）
内存1 TiB
GPU8 × NVIDIA A800 80GB （不可用于 QBlade FVW，路径死锁）
GPU 探索结论：QBlade 2.0.8.6 SIL 的 GPU 路径（OpenCL）对 propeller 工况存在死锁 bug：
  • NREL_5MW（QBlade 自带 sample）+ GPU 可跑通
  • propeller + GPU 在 initializeSimulation 后 advance 永久 hang
  • 3090 与 A800 都复现，多卡并行触发 CL_INVALID_DEVICE (-33) core dump
最终采用 CPU 多进程并行，每 worker 32-thread OpenMP 池。

8.2 进程隔离

node6 (160 core)
  └─ python run_data_gen_parallel.py --workers 16 --omp-threads 8
      ├─ main process (Pool dispatch)
      └─ worker 0..15 (fork)
          ├─ /tmp/lfm_w<pid>/
          │   ├─ code/                 ← 深拷贝 (~164KB)
          │   ├─ QBladeCE_2.0.8.6/     → symlink (read-only)
          │   └─ QBlade_data/          ← 深拷贝 (~80MB)
          │       └─ QBlade_sim/...    ← 每 worker 独立 .sim/.bld 写
          └─ chdir(/tmp/lfm_w<pid>/code/Simulation_QBlade)
              └─ os.getcwd() = 真实独立路径
                  (避免 symlink chdir 跟随回 source)

8.3 OMP 线程限流

每 worker 启动时设置：

os.environ["OMP_NUM_THREADS"] = "8"
os.environ["OMP_THREAD_LIMIT"] = "8"
os.environ["OPENBLAS_NUM_THREADS"] = "8"
os.environ["MKL_NUM_THREADS"] = "8"
os.environ["QT_THREAD_POOL_MAX_THREAD_COUNT"] = "8"

16 worker × 8 thread = 128 核占用（留 32 给系统/IO/QBlade Qt helper）。

之前默认 32 thread 时 4 worker 触发 900+ runnable thread，load avg 200+，单几何 wall clock 退化 8×。
