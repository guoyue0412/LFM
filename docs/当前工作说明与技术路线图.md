## 3. 技术路线图

## 阶段 A（立即执行，1-2 周）
目标：稳定产出可继续训练的数据，不中断主流程。

- **A1. 采集策略固定**
  - GPU 主进程持续跑主序列几何；
  - CPU 守护进程低占用运行（默认 1 worker，8 线程）；
  - 禁止手工重复拉起 CPU 批任务，避免冲突。
- **A2. 过程可观测**
  - 每日记录：新增 `sample_XXXX.pkl` 数、GPU 温度/频率区间、失败工况数；
  - 每 24h 生成一次进度快照（几何完成数、预计剩余时间）。
- **A3. 质量闸门**
  - 每完成 N（建议 20）个几何，抽样检查 `case_results` 是否满 72；
  - 发现缺失工况时自动标记并回补。

交付物：
- 持续更新的采集日志；
- 完整可训练样本目录（格式统一）。

## 阶段 B（短中期，2-4 周）
目标：缩短单机周期，提升单位时间有效样本。

- **B1. 热瓶颈优化**
  - 固定功耗上限（当前 100W），并以温控优先策略运行；
  - 增加机箱散热/环境降温（这是恢复接近历史 22min/工况的核心前提）。
- **B2. 工况优先级采样**
  - 先跑对代理模型最敏感的工况子集（例如中高 RPM、典型风速）；
  - 采用“先覆盖后补全”策略，减少前期等待。
- **B3. 自动补位调度升级**
  - 将 CPU 守护进程扩展为阈值触发（CPU/GPU 温度或负载超阈值时自动降并发）。

交付物：
- 加速后的采集配置基线；
- “优先级工况集”及其覆盖报告。

## 阶段 C（中长期，4-8 周）
目标：将数据采集与优化训练形成闭环迭代。

- **C1. 代理模型再训练节奏**
  - 每新增一批几何（建议 30-50）触发一次增量训练；
  - 输出误差报告与 OOD 覆盖率报告。
- **C2. 优化闭环**
  - PPO/CMA-ES 新候选 → QBlade 校核 → 差异度分析 → 反哺训练集；
  - 对高差异样本做主动学习加采（重点采边界/高收益区域）。
- **C3. 交付导向**
  - 固化“可复现实验包”：配置、模型、日志、最优设计与对比图。

交付物：
- 迭代版代理模型；
- 经过 QBlade 校核的最优设计候选集；
- 研究结题报告材料。

## 4. 推荐执行规范（避免资源问题）

- 仅保留一个 GPU 主进程（禁止重复启动同参数 GPU 任务）。
- CPU 只通过 `run_cpu_daemon.py` 启动，不直接批量开多个 `get_data.py --device CPU`。
- 默认低占用参数：
  - `--workers 1 --omp-threads 8`（优先稳定）；
  - 需要提速时再提升为 `workers 2`，并观察 30 分钟资源曲线后决定是否长期保持。
- 每次调整并发后，记录 3 项：CPU 负载、GPU 温度、单位时间新增几何数。

## 5. 下一步建议（可直接执行）

1. 维持当前“GPU 主 + CPU 低占用补位”连续运行 24 小时。
